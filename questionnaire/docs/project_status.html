Lab Documentation Prototype

A tablet app for documenting lab work at the bench. It covers the daily instrument check (first run of the day) and experiment answers (which instrument, product and lot were used). It will run in Docker on a local server.

What the app does today

Every session starts on the landing page. The answer to "Is this the first run of the day?" decides which second page opens.

Page 1 · Landing

Who, when, what

  • The user picks their name and the date (future dates are not allowed).
  • They answer whether this is the first run of the day. If it isn't, they also pick the experiment type and the type of run (regular, retest or pre-test), which is saved with every answer.
  • A status box shows which instruments already had their daily check on that date.
Page 2a · First run

Daily instrument check

  1. Instrument: shows the software and firmware versions. Corrections are saved when the user presses Confirm.
  2. Positive control: lot, valid? The rerun is asked about only if the control was not valid.
  3. Negative control: the same questions.
  • One check per instrument per day. This holds even when two people save at the same time.
  • Missing control lots can be added.
  • At the end, "Continue to an experiment" leads straight on.
→ data/daily_checks.csv
Page 2b · Experiments

Detection Capability, Linearity

  • The instrument list only shows instruments with a daily check on that date. A notice explains what to do when there are none.
  • Product, then its lot. Missing lots can be added.
  • Instrument fluids: system buffer and system fluid lots, with the expiry date to confirm against the bottle; new lots with expiry date; a rare second lot.
  • Sample preparation: vortexed, thawed, and for how many minutes.
  • After a save, the app confirms it and clears product and lot. The instrument stays selected.
  • "Your answers for this date" lists the user's own answers.
→ data/responses.csv

Change log: who changed what, and when

The base lists (instruments, controls, products) are never edited by the app. Corrections are written to a separate log, and the app shows the base lists with the logged changes applied. For versions, the latest change wins. Every change asks for confirmation first, the app shows who made it and when, and it can be undone ("Undo this change", "Remove this lot"). An undo is logged as a new change; nothing is deleted. There is no approval by a second person.

Look and usability

  • Sebia blue #004195 as the one accent colour.
  • Built for a tablet at the bench: every tap target is at least 48 px (easier with gloves), and it works in portrait and landscape.
  • Contrast checked: text is at least 4.5:1 and field borders at least 3:1.
  • The page language is set, keyboard focus moves to each new page, and "saved" messages are read out by screen readers.
  • Native dropdowns, which work better on touch screens.
  • Fully offline: icons (Font Awesome, open licence) and styles are served from the app itself.

How the code is organised

app/logic is plain R with no Shiny, so it is easy to test. app/view holds the Shiny modules. main.R puts them together.
